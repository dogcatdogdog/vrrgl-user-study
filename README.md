# 用户实验平台

为论文《A GNN-Based Graph Layout Method for Improving Node-Centric Readability》第 5 章补充的**用户实验**平台。

## 这个项目要做什么

验证一个主张：**LPFD 生成的图布局，是否让「围绕单个节点的一跳邻域」更容易被读懂。**

用两个任务来测（**T1 与 T2 启用，T4 已关闭**）：

| 任务 | 问什么 | 对应设计目标 | 默认 |
|---|---|---|---|
| **T1** 邻居识别 | 点击所有与高亮节点**直接相连**的节点（判分按真实一跳邻域） | D1（距离可比）、D4（保持结构差异） | ✅ 启用（事实型措辞） |
| **T4** hub 识别 | 两个高亮节点中，哪个连接更多？ | **D2（角度分布）** | ⛔ 关闭（pilot 天花板） |
| **T2** 邻居计数 | 高亮节点有多少个直接邻居？ | D1、D3 | ✅ **启用** |

> **T1 的措辞有变体**：当前用事实型（*"directly connected"*），可用 `CONFIG.tasks.T1.wording = 'perceptual'` 切到 GVRRI 的感知型（VRR，*"appear to belong to the neighborhood"*）。二者交互与判分完全相同，只是一行文字不同。

**完整任务规格见 `docs/03_任务定义.md`。**

自变量：**布局**（LPFD / KK / FR / FA2）× **节点度数档位**（低 **2–8** / 高 **≥16**，高档不设上限）

- **16 张图**（每档 8 张），每任务 16 trial，**T1 + T2 共 32 trial**（约 30–35 分钟）
- 数据源：**自选数据集里 ≤110 节点的原生图**，**不裁剪、不重新布局**

> **两个并列主假设**：
> - **H1** LPFD 的任务准确率更高
> - **H2** LPFD 的优势随节点度数变化（layout × degree 交互）
>
> ⚠️ **不要用几何指标去预测或排除任何度数区间。** 论文的核心论点就是「几何指标不能代表可读性」——用它去预测可读性实验是自相矛盾的。
>
> 这个指标尤其不能用，因为**它取最小值（最坏一对边）**：「值低」不等于不可读，「值高」不等于容易。
> 所以 **26+ 度的图保留**（指标 0.02 只说明有一对边重叠），**2–8 度也不排除**。



> 🔴 **2026-09-28 设计变更**：数据源从「case 派生 ego network」改为「自选小图原生布局」。
> 原因：ego 窗口的局部几何被破坏（seed 处角均匀度实测 0.02–0.09，高度数时四种方法全部塌到 0.05 以下），且本地无法重新布局。
> **影响**：`build_stimuli.py` 的 ego 抽取部分作废，`stimuli/` 需重新生成。**App 本身不受影响**（配置驱动）。
> 详见 `docs/02_数据方案.md` §1。

## ★ 两条最容易做错的地方

### 1. 绝对不能高亮 hub

论文插图 `paper_figure.py` 把 hub 画成**红色、放大 1.6 倍**。用户实验**绝不能**这么做——否则 T4（哪个节点连接更多？）会退化成「找红色的」，任务直接失效。

**所有节点必须同色同大小。**

### 2. 归一化用**包围盒（fit-to-view）**

**已定案，不是可选项。**

三个参照物全都指向它：

| 参照物 | 做法 |
|---|---|
| **GVRRI**（我们参照的已发表实验） | `resistance.py::plot_network`：包围盒 + 10% 留白 |
| **我们的论文插图** | `paper_figure.py` L139–146：每个子图 fit 自己的包围盒 + 8% 留白 |
| **用户的真实体验** | 打开一张图就是「适应窗口」 |

**采用它的直接好处：溢出从定义上不可能发生**——不需要 shrink-to-fit、不需要筛图排除"太大"的 ego、不需要自适应节点半径。

**已知代价**：紧凑的布局会被放大 → 看起来更分散。这是**布局的真实优势**，不是渲染 artifact。

> ⚠️ pilot 时要另产一套「中位边长归一化」的刺激做稳健性对比（`build_stimuli.py --normalization`）。

详见 `docs/01_平台设计.md` §2.2。

### 导出数据

数据**不会自动存到硬盘** —— 它保存在浏览器的 `localStorage` 里，**必须主动导出**。

```
http://127.0.0.1:8000/src/?export=all
```

浏览器会下载 `vrrgl_all_sessions_<日期>.json`（在「下载」文件夹），页面上同时列出
每位被试的编号与完成状态，便于核对：

```
导出完成 / Export complete
L001 — ✅ 已完成 — 32 trials（+ 2 attention）
L002 — ⏳ 未完成 — 12 trials
共 2 位被试（其中 1 位已完成）
```

- **包含未完成的会话**（标 ⏳）—— 能发现「有人做到一半走了」
- 可以反复导出，每次生成带日期的新文件，不覆盖
- 单个被试也可在**结束页**点「下载我的数据」

> 📱 **下载的文件名变成一长串 GUID（如 `b862bfeb-…`）、「在文件夹中显示」也打不开？**
> 两种常见原因：
> 1. **在自动化控制的浏览器窗口里操作**（Playwright / 远程调试窗口）——下载会被存到临时目录
>    `%LOCALAPPDATA%\Temp\playwright-artifacts-*`，并以 GUID 命名。**真实被试请用普通浏览器窗口**，
>    不要用自动化窗口。
> 2. 手机 Chrome / 内嵌浏览器不支持给 Blob 下载指定文件名。
>
> 两种情况下**数据本身都完整**——打开文件确认 `participant_id` 后改名为 `<被试编号>.json` 即可。
> 结束页另有「分享 / 发送数据文件」按钮，支持系统分享的设备可直接发微信/邮件，文件名不会丢。

> ⚠️ **数据按「源」隔离**：`127.0.0.1` 与 `localhost` 不同、换端口也不同、换浏览器更不同。
> 实验期间固定用一个网址，否则导不到之前的数据。

### 众包（Prolific）

Prolific 会自动传入 `PROLIFIC_PID`，不需要手动指定。需要：
- `CONFIG.consent.condition = 'prolific'`
- 填好 `CONFIG.consent.screenOutUrl`（**不是**完成码）与 `CONFIG.prolific.completionCode`
- `CONFIG.storage.mode = 'post'` + `endpoint`（否则数据只留在被试自己的浏览器里）

**为什么不直接用 `python -m http.server`**：Windows 上 `mimetypes` 会读注册表，把 `.js` 映射成
`text/plain`，浏览器对 `<script type="module">` 做严格 MIME 检查 → 模块全部加载失败。
`tools/serve.py` 显式钉住 MIME 类型，并且是**多线程**（ES module 图会并发请求，
单线程服务器会让连接被拒），同时禁用 304 协商缓存（否则改了代码刷新还是旧的）。

**为什么不能直接双击 `index.html`**：App 要 `fetch` 刺激数据，`file://` 下会被 CORS 拦掉。
App 里对这种情况有专门的错误提示。
