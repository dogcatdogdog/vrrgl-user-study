# 任务定义（开发规格）

> 本文档定义被试要做**哪几个任务**、每个任务的**精确题干、交互、判分、记录字段**。
> 配套文档：`01_平台设计.md`（架构与渲染规范）、`02_数据方案.md`（刺激数据）

## 0. 任务总览

**三个任务，两个必做，一个可选。**

| 编号 | 任务 | 一句话 | 对应设计目标 | 状态 |
|---|---|---|---|---|
| **T1** | 邻居识别 | 找出与高亮节点直接相连的所有节点 | D1（距离可比）、D4（保持结构差异） | **必做** |
| **T4** | hub 识别 | 两个高亮节点中，哪个连接更多？ | **D2（角度分布）** | **必做** |
| **T2** | 邻居计数 | 高亮节点有多少个直接邻居？ | D1、D3（边长一致） | 可选，pilot 后定 |

### 为什么是这三个

```
论文的四个设计目标          对应的可测任务
─────────────────────────────────────────────
D1 一跳邻居距离可比    ──→   T1（找邻居）、T2（数邻居）
D2 入射边角度分布均衡  ──→   T4（比度数）        ★ 唯一有文献支撑的落点
D3 一跳邻域边长一致    ──→   T1、T2（无独立研究支持，见 §5）
D4 保持局部结构差异    ──→   T1（找邻居）
```

**T4 是 D2 唯一的实验抓手。** Huang, Hong & Eades (JGAA 11(2):397–429, 2007) 发现角分辨率显著影响「hub / 重要性感知」——而 D2 正是关于角度分布的。文献同时指出角度对「数邻居」影响很小，所以 **D2 只能靠 T4 来验证**。

## 1. 任务与假设的对应

| 假设 | 用什么检验 | 地位 |
|---|---|---|
| **H1** LPFD 的任务准确率更高 | T1、T4 的 layout 主效应 | **主假设** |
| **H2** LPFD 的优势随节点度数变化 | T1、T4 的 **layout × degree 交互** | **并列主假设** |
| H3 LPFD 的反应时更短 | T1、T4 的 log(RT) | 次要 |
| H4 LPFD 的主观可读性得分更高 | 问卷（见 §6） | 次要 |

### 关于 H2：保留为**并列主假设**

**理由**：两档的**任务难度不同**。**难度本身可能与布局交互**——布局差异在难任务上可能被放大，也可能被掩盖。这条推论**完全不需要经过几何指标**。

> ⚠️ **不要用几何指标去预测或排除任何区间。**
>
> 论文的核心论点正是「几何指标不能代表可读性」。**用一个已知不能代表可读性的量，去预测或排除可读性实验的条件，是自相矛盾的。**
>
> 这个指标尤其不能用，因为**它取的是最小值**：
> ```
> 角均匀度 = 最小相邻边夹角 ÷ 理想夹角     ← min，不是 mean
> ```
> **「值低」只说明有一对边几乎重叠，不说明整个邻域糊；「值高」也不说明任务容易。**
>
> | 度数 | 指标值 | ⚠️ 不能据此判定 |
> |---|---|---|
> | 2–4 | 0.50–0.68 | 0.68 远不是「完美均匀」→ **不是天花板** |
> | 26+ | 0.02 | 只说明**有一对边**重叠 → **不是地板** |
>
> **我曾两次用这个指标做取舍，两次都错。**

**所以 H2 是一个待检验的假设，不是可以预先否定的结论。** 哪些区间会地板/天花板，**只能由 pilot 回答**。

> **「node-centric」这个定位仍有第 5 章的证据** —— LNP/LAR（只在 hub 上算）优于 NP/AR（全局）。用户实验是对它的**独立验证**，而不是它的推论。

## 2. T1 —— 邻居识别

### 2.1 研究目的

测被试能否**准确地找出某个节点的一跳邻居**。这是「局部分析」最基本的操作，对应 D1 与 D4。

### 2.2 题干（可直接使用）

> **Click on all nodes that are directly connected to the highlighted node.**

（点击与高亮节点**直接相连**的所有节点。）

#### 关于 T1 措辞：两个变体，共用同一个真值

由 `CONFIG.tasks.T1.wording` 控制（`'factual'` 默认 / `'perceptual'`）。

| | **事实型**（默认） | **感知型**（GVRRI 的 VRR 协议） |
|---|---|---|
| 题干 | *"...directly connected to the highlighted node."* | *"...appear to belong to the neighborhood of the highlighted node."* |
| **真值** | ✅ 真实一跳邻域 | ✅ **完全相同** |
| **判分** | `Jaccard(S, N)` | ✅ **完全相同** |
| **交互** | 单击 + 框选 | ✅ **完全相同** |
| 被试的**认知过程** | **沿边逐条追踪**（逐个验证） | **格式塔分组**（凭整体印象圈一片） |
| 实际测到什么 | **邻域感知 ＋ 边追踪** | **只要邻域感知** |
| 对什么敏感 | 边交叉、边长、**以及**空间邻近 | **主要是**空间邻近、局部密度 |

> ⚠️ **注意**：两种措辞**共用同一个真值**（图结构给定的一跳邻域）与同一套判分公式。
> 「没有客观真值」说的是 **GVRRI 的处境**（他们研究的**就是感知本身**），**不是我们的**。
> 我们问的是「哪种布局让**真实的**邻域更容易被感知到」—— 真值是客观的。

**两者的短板性质不同**：

| | 事实型 | 感知型 |
|---|---|---|
| 短板 | **测量不纯** —— 混入了边追踪能力 | **数据质量风险** —— 「我感觉」→ 可能不认真；指令可能被误解 |
| 后果 | 效应变小（**保守偏差**，可接受） | 数据**无法挽救**（被试乱答） |
| 与论文主张 | 间接 | **直接** |
| 与 GVRRI 对话 | ❌ | ✅ 直接回应他们的 open question |

**默认用事实型**，理由是风险更可控。**感知型的优势可在 pilot 中验证**——两种措辞交互与判分完全相同，只差一行字。各招 8 人跑一遍，看：

- 感知型下被试选择的**方差**是否更大（→ 没理解或没认真）
- 感知型下各布局的**差异是否更明显**（→ 它确实更灵敏）

若 pilot 显示感知型数据干净，就切过去。

### 2.3 界面

```
┌──────────────────────────────────────┐
│                                      │
│          [ 图 ]                       │
│     · 目标节点蓝色填充（仅此一个）           │
│     · 其余节点统一灰填充、半径 5px           │
│     · 已选中节点加红描边（不改填充色）        │
│                                      │
├──────────────────────────────────────┤
│  Click on all nodes that are directly │
│  connected to the highlighted node.   │
│                                      │
│              [   Submit   ]           │
└──────────────────────────────────────┘
```

### 2.4 交互

| 操作 | 行为 |
|---|---|
| **单击节点** | 切换该节点的选中状态（再点一次取消） |
| **拖拽矩形** | 框选：落在矩形内的节点**全部加入**选中集（不取消已有的） |
| 被选中的视觉 | 节点外加一圈高亮描边（与目标节点的轮廓区分开，建议用不同颜色或虚线） |
| **Submit** | 至少选中 1 个节点才能点击 |

> **两种交互都必须支持。** 众包环境下被试设备各异，手绘圈选在触控板上体验很差；矩形框选 + 单击是最稳妥的组合。

### 2.5 判分

设 `S` = 被试选中集合，`N` = 目标节点的真实一跳邻域。

```javascript
jaccard   = |S ∩ N| / |S ∪ N|          // 主指标，∈ [0,1]
precision = |S ∩ N| / |S|              // 选中的里面有多少是对的
recall    = |S ∩ N| / |N|              // 真实邻居里找回了多少
exact     = (S 与 N 完全相等) ? 1 : 0
missed    = |N \ S|                     // 漏掉的邻居数
false_pos = |S \ N|                     // 多选的节点数
```

**主指标用 `jaccard`**（连续值，比 0/1 更有统计功效）。

### 2.6 记录字段

```
stimulus_id, task="T1", graph_id, layout, degree_level,
target_node, target_degree,
response_selected: ["n3","n7",...],
jaccard, precision, recall, exact, missed, false_pos,
n_selected, rt_ms, timestamp, visibility_switches
```

### 2.7 计时

从**图渲染完成**（最后一帧绘制完毕）到**点击 Submit**。用 `performance.now()`。

### 2.8 练习时的反馈

练习 trial 提交后显示：
> 正确答案有 **6** 个邻居，你找到了 **4** 个，多选了 **1** 个。（Jaccard: 0.57）

### 2.9 风险

| 风险 | 说明 |
|---|---|
| **被试可能不理解"directly connected"** | 说明页要配图示意：「A 和 B 之间有一条边，就算直接相连」 |
| **框选时误选** | 允许单击取消，且提交前可反复修改 |

## 3. T4 —— hub 识别

### 3.1 研究目的

**这是验证 D2（角度分布）的唯一任务。**

测被试能否判断两个节点中哪个的连接更多。Huang et al. (2007) 的实验证据表明，角分辨率影响人对节点重要性/地位的感知——而 D2 正是为改善角度分布而设。

### 3.2 题干（可直接使用）

> **Which of the highlighted nodes has more direct connections?**

（两个高亮节点中，哪个有更多直接连接？）

### 3.3 界面

```
┌──────────────────────────────────────┐
│          [ 图 ]                       │
│     · 两个节点都是相同样式的蓝色填充          │
│     · 其余节点统一灰填充、半径 5px           │
│     · 点击任一蓝节点即提交（无持续选中态）     │
│                                      │
├──────────────────────────────────────┤
│  Which of the highlighted nodes has   │
│  more direct connections?             │
│                                      │
│   （点击两个高亮节点之一即提交）            │
└──────────────────────────────────────┘
```

### 3.4 交互

| 操作 | 行为 |
|---|---|
| **点击任一高亮节点** | **立即提交**，不设确认按钮 |

> **为什么不要确认按钮**：多一次点击会往反应时里注入噪声（决策已完成但还要找按钮）。直接点击即提交，把决策时间与操作时间对齐。

### 3.5 配对构造规则

对每个 trial，从图中挑**两个节点**作为高亮对象：

```python
# 必须满足两条，防止"差一点点"导致猜
|deg_a - deg_b| >= 2                     # 绝对差至少 2
max(deg_a,deg_b) / min(deg_a,deg_b) >= 2 # 比值至少 2:1

# 同时：度数更高的那个必须落在本 trial 的度数档区间内
#   高试次：deg_max ∈ [16, 25]
#   低试次：两个节点都在 [5, 8]
#   （度数档定义见 02_数据方案.md §3.2）
deg_max_node 落在该 trial 的 degree_level 区间
```

**两个目标节点的渲染样式必须完全相同**（同样的蓝色填充 `#2196f3`、同样的半径 5px、无额外描边）。**不得**通过大小、颜色、位置、描边暗示哪个度数更高。

> 参照物：普通节点是**灰色填充**，因此「蓝色」在两个目标之间是中性的——它只标识「这是目标」，不携带度数信息。

### 3.6 判分

```javascript
correct = (clicked_node === argmax(deg_node_a, deg_node_b)) ? 1 : 0
```

### 3.7 记录字段

```
stimulus_id, task="T4", graph_id, layout, degree_level,
pair: ["n3","n17"],
degree_pair: [18, 4], degree_ratio: 4.5,
response_clicked: "n3",
correct, rt_ms, timestamp, visibility_switches
```

### 3.8 计时

从**图渲染完成**到**点击节点**。

### 3.9 练习时的反馈

> 正确。节点 A 有 **18** 个连接，节点 B 有 **4** 个。

### 3.10 风险

| 风险 | 说明 | 缓解 |
|---|---|---|
| **天花板效应** | 度数差很大时太简单 | 配对时**不总是取最大差**——建议一半是 2:1（接近），一半是 4:1 以上（明显） |
| **地板效应** | Zhao et al. TVCG 2025 证明度数估计本身就难 | **pilot 中验证**；若基线都做不对，调整配对规则 |
| **被试数两个节点的邻居** | 比数一个更费时 | 接受；反应时本来就预期较长 |

## 4. T2 —— 邻居计数（可选）

### 4.1 研究目的

直接测「数邻居」这个操作，对应 D1。文献中这是**最经典也最难**的图任务之一（Zoss 2018: *"Number of links actually hardest"*）。

### 4.2 题干

> **How many nodes are directly connected to the highlighted node?**

### 4.3 交互

```
① 数字输入框  ② Submit 按钮
```

### 4.4 判分

```javascript
error = |answer - true_degree|     // 绝对误差，主指标
exact = (error === 0) ? 1 : 0
```

**主指标用 `error`**（连续值），辅以 `exact`。

### 4.5 ⚠️ 加不加要 pilot 决定

Zoss (2018) 的研究显示这是所有任务里最难的一项，**有明确的地板效应风险**——如果各布局下被试都数不对，就测不出差异。

**建议：先跑 T1 + T4，pilot 数据显示有余力再加 T2。**

## 5. 关于 D3 的说明（重要）

D3 是「一跳邻域内边长相对一致」。**本任务的三个任务都不直接测 D3**，原因：

1. **文献中没有验证过的、对应「边长一致」的任务。** Purchase 的 UML 研究甚至给出了**负面证据**（edge length variation 无显著结果）
2. LPFD 在 EU/LEU（边长一致性）上**是六种方法中最低的**——这正是因为它给每条边学一个独立的理想长度 `l_ij`，那是 **D4 的实现方式**，与 D3 在架构层面直接对立
3. 消融实验证明 LPFD **有能力**做到极高的一致性（EU-only 配置在逐节点口径下达 0.9942，超过最强基线 0.9202），但代价是布局退化

**所以 D3 的处理方式是**：在论文第 5 章如实说明这是**有意识的取舍**，而不是为它设计一个用户任务。详见 `D:\VRRGL\paper_work\ch5\90_fix_list.md` 条目 F16、F18。

## 6. 问卷

### 6.1 数据采集流程中的位置

```
人口学               →  实验前（含「图论熟悉度自评」1–7，作协变量）
每 trial 易读性评分    →  正式试次中（可配开关）
NASA-TLX             →  实验结束后一次
PREVis               →  实验结束后一次（⚠️ 适配性待确认，见 §6.5）

✗ 图素养前测 —— 【已取消】，理由见 §6.3
```

### 6.2 人口学问卷（实验前）

| 题 | 类型 |
|---|---|
| 年龄 | 数字输入 |
| 性别 | 单选（男 / 女 / 其他 / 不愿透露） |
| 专业/领域 | 单选（计算机 / 设计 / 其他，可填） |
| **图论熟悉度自评** | 1–7 Likert（「你熟悉节点、边、度数这些概念吗？」） |
| 平时看图的频率 | 单选（每天 / 每周 / 每月 / 很少 / 从不） |

> 「图论熟悉度」与「看图频率」**作为协变量**进入分析。

### 6.3 图素养前测 —— **默认关闭，不做**

> 🔴 **决定（2026-09-28）：不设图素养前测。** `CONFIG.survey.literacy = false`

**理由（三条）：**

**① 没有可用的、经过验证的量表**

| 候选 | 为什么不能用 |
|---|---|
| **Zoss NVL**（Zoss et al. 2019, TVCG） | 量表本体在论文补充材料里，`github.com/amzoss/netvislit` **只提供分析脚本和数据，没有题项**。数据拿不到 |
| **GGR**（Galesic & Garcia-Retamero 2011, 13 题） | 测的是**统计图表**素养（柱状图/折线图），**不是网络图**——构念不对 |
| **自编** | **违背本项目已定的原则**（对 PREVis 说过：「不适用就找权威替代，不要自己单纯构建」） |

**② 信度不够的协变量会降低功效，不是提升**

```
协变量只有在【信度足够高】时才提升功效。测量误差会：
  ① 衰减它与结果的相关性  →  控制得不干净
  ② 白占一个自由度        →  残差自由度减少
净效果可能为负。
```

自编量表最容易落在「既不可靠、又占自由度」的区间——**「你以为控制了图素养，其实控制了个常数」**。

**③ 组内设计里，协变量本来就不是必需品**

```
accuracy ~ layout * degree + (1|participant) + (1|graph)
                              ↑
                    参与者的随机效应已经吸收了「个体能力」这部分方差
```

**协变量唯一的作用是「再榨一点功效」，不影响效度。** 而一个不可靠的协变量可能榨成负的。

### 6.3b 替代做法（两件补强，成本为零）

| 补强 | 做法 | 为什么不必前测差 |
|---|---|---|
| **① 自评留在人口学** | 保留「图论熟悉度自评」(1–7) 作协变量 | 主观，但**没有测量误差累积**的问题 |
| **② 报告方差成分** | 分析里报 `(1\|participant)` 的方差估计 | **直接回答「个体差异有多大」**，比一个未验证的协变量更有信息量 |

> **若 pilot 显示个体差异确实很大**，再回头考虑加协变量——**但届时必须用经过验证的量表**。

### 6.3c 若将来要加回前测

**必须做两件事之一**：
1. 拿到 **Zoss NVL 量表本体**（渠道：Zoss et al. 2019 的补充材料；或直接联系 Zoss 本人；或问 GVRRI 那组——**中南大学 + 奇安信，他们正在提供本项目的图数据**）
2. 若仍用自编题，则**不得当协变量**，只能降级为「熟悉化练习 + 注意力检查」，并在论文里写明它不是经过验证的量表

**拿到量表后替换 `stimuli/literacy.json` 即可，代码不用改**（接口已预留）。

### 6.3-old 原方案（已废弃，保留备查）

从 **Zoss NVL 题库**（github.com/amzoss/netvislit）取 **5–8 题**，覆盖：数边数、平均度、最高度节点、聚类数。

**计分**：用该题库的 Log Absolute Error 方式，产出 `literacy_score`。作为协变量。

### 6.4 每 trial 易读性评分（可配，`CONFIG.survey.perTrialEase`）

**建议启用。** 每个正式 trial 作答后追加一个极简评分：

> **How easy was it to answer this question?**
> 1 = 非常难 … 7 = 非常容易

**为什么重要**：这是唯一能拿到**逐布局主观数据**的途径。没有它，主观对比只能做整体的，无法归因到具体布局。

**代价**：每 trial 多约 2 秒 × 32 trial ≈ 64 秒。可接受。

> 若 pilot 显示打断心流，可改为**每 6 题问一次**（配置项 `perTrialEaseEveryN`）。

### 6.5 PREVis（实验后一次）—— ⚠️ 适配性待确认

**PREVis**（Cabouat et al., IEEE VIS 2024）是**目前唯一经过验证的感知可读性问卷**，4 个子量表，α / ω 在 0.87–0.96 之间，问卷与施测指南开源于 `osf.io/9cg8j`。

**但它有个适配问题**：PREVis 是为「评价**一个**可视化」设计的，而我们的被试在实验中看了**几十张不同的图、四种不同的画法**。直接问「请评价这个可视化」会指代不明。

**三个处理方案**：

| 方案 | 做法 | 代价 |
|---|---|---|
| **A**（推荐） | 改用 §6.4 的逐 trial 易读性评分，**放弃 PREVis** | 失去经验证的量表背书 |
| **B** | 改造 PREVis 的措辞，在每个**任务块结束时**对「刚才这一组图」整体评一次 | 需说明对原量表的改动 |
| **C** | 先读 PREVis 原文与施测指南，确认能否按「多次施测」使用 | 需先做文献工作 |

> **开发时请先按方案 A 实现**（逐 trial 评分），同时把 PREVis 的题目做成**可配置的问卷模块**，等方案确定后再决定是否启用。

### 6.6 NASA-TLX（实验后一次）

6 个分量表，各 0–100（或 7 点）：

```
Mental Demand        脑力需求
Physical Demand      体力需求
Temporal Demand      时间压力
Performance          自评表现（反向计分）
Effort               努力程度
Frustration          挫败感
```

末尾追加**成对比较**（15 对，用于加权）；若嫌长可用**原始 TLX 等权版本**（配置项 `CONFIG.survey.tlxWeighted`）。

### 6.7 主观偏好排序（可选，`CONFIG.survey.preference`）

实验最后展示**同一张图的四种布局并排**，问：

> **Which of these layouts is the easiest to read? Please rank them (1 = easiest).**

**注意**：这个屏**明确告诉被试有四种画法**，所以必须放在**所有正式试次之后**，否则会破坏盲测。

### 6.8 记录格式

```json
"questionnaire": {
  "demographics": { "age": 24, "gender": "F", "field": "CS",
                    "graph_familiarity": 4, "graph_frequency": "weekly" },
  "literacy": null,          // 前测已取消，恒为 null（见 §6.3）
  "per_trial_ease": [ { "trial_index": 0, "ease": 5 }, ... ],
  "nasa_tlx": { "mental": 40, "physical": 15, "temporal": 25,
                "performance": 30, "effort": 45, "frustration": 35 },
  "preference": { "ranking": ["LPFD", "KK", "FR", "FA2"] }
}
```

> `preference.ranking` 里的布局名**只在数据文件里出现**，界面上必须是「左/中/右」这类位置指代。

## 7. 练习与质量控制

### 7.1 练习 trial（题数由 config 推导）

> **题数规则**：`CONFIG.practiceTrials = { T1: 2, T4: 2, T2: 1 }`，**仅对 `enabled` 的任务生效**。
> - **T2 关闭（默认）→ 4 题**（T1 × 2 + T4 × 2）
> - T2 开启 → 5 题（+ T2 × 1）
>
> 下表按默认的 4 题列出。

| # | 任务 | 图来源 | 反馈 |
|---|---|---|---|
| 1 | T4 | **刺激池之外的图** | 显示正确答案 |
| 2 | T1 | 同上 | 显示 Jaccard 与漏选/多选数 |
| 3 | T4 | 同上 | 显示正确答案 |
| 4 | T1 | 同上 | 显示 Jaccard |

练习图**必须不在正式刺激里**（否则产生学习效应）。

### 7.2 Attention check（2 个）

在主试次之间插入 2 个独立屏幕：

> **To confirm you are reading carefully, please type the word GRAPH in the box below.**

不通过者标记为 `failed_attention`，可在分析时剔除（但需报告剔除数量）。

### 7.3 强制休息

每 12 个 trial 后插入 30 秒倒计时休息屏，可跳过。

## 8. 试次流程

```
① 示例讲解（4 个示例图，说明目的/概念/任务/流程，演示界面）  ← GVRRI 做法
   ↓
② 练习 × 4（T2 关闭时；开启则 5）——题数由 config 推导，见 §7.1
   ↓
③ 正式 trial × 48（每个任务 24）
   │   · 顺序 = Latin square 分派后的固定排列（每张图只出现一次）
   │   · 每题作答后 → 逐 trial 易读性评分（1 题 1–7，见 §6.4）
   │   · 每 12 题 → 强制休息 30 秒
   ↓
④ 问卷：NASA-TLX + 完整 PREVis（方案见 §6.5）+ 可选偏好排序
   ↓
⑤ 半结构化访谈 / think-aloud（可选，GVRRI 做了，用于定性分析）
```

**每个 trial 的标准流程**：

```
1. 显示题干文字（0.5 秒后淡出，避免反复阅读干扰计时）
2. 渲染图 → 记录 render_complete 时间戳
3. 开始计时
4. 被试作答
5. 记录答案与 rt_ms
6. 清屏 → 下一个 trial（500ms 间隔）
```

## 9. 单位与格式约定

| 项 | 约定 |
|---|---|
| 反应时 | 毫秒，整数 |
| Jaccard / precision / recall | 保留 4 位小数 |
| 度数 | 整数 |
| 时间戳 | Unix ms |
| 节点 ID | `n0`, `n1`, ... （已匿名化，见 `02_数据方案.md` §5） |
| 布局标签 | `"LPFD"` / `"KK"` / `"FR"` / `"FA2"` |
| 度数档位 | `"low"` / `"mid"` / `"high"` |

> ⚠️ `layout` 与 `degree_level` 字段**只记录在数据里，绝不能显示在被试界面上**。

## 附录：任务来源文献

- **Lee, Plaisant, Parr, Fekete & Henry.** *Task Taxonomy for Graph Visualization.* BELIV 2006
  → 「Find the set of nodes adjacent to a node」（T1）、「How many nodes are adjacent to a node?」（T2）、「Which node has a maximum number of adjacent nodes?」（T4）
- **Ghoniem, Fekete & Castagliola.** *Node-link vs matrix-based representations.* InfoVis 2004 / *Information Visualization* 4(2), 2005
  → `findNeighbor`（T1）、`linkCount`（T2）、`mostConnected`（T4）
- **Huang, Hong & Eades.** *Effects of Sociogram Drawing Conventions and Edge Crossings.* JGAA 11(2):397–429, 2007
  → **角分辨率影响 hub / 重要性感知**（T4 的依据）
- **Zhao et al.** *Investigating Visual Perception of Degree Centrality in Graph Visualization.* TVCG 31(6):3679–3692, 2025
  → 度数估计本身就难，尤其差值小时（T2、T4 的风险依据）
- **Zhao et al.** *GVRRI: Identifying visual receptive regions in node–link diagrams for node-centered graph analysis.* C&G 138:104641, 2026
  → 感知邻域协议（T1 的替代变体）
- **Ehlers et al.** *Me! Me! Me! Me! A study and comparison of ego network representations.* C&G 125:104123, 2024
  → `T_neighbors`、`T_degree`、`T_common` 的任务措辞参考
