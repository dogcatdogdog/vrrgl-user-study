## ✅ 处理结果（2026-09-28 由文档维护方回填）

### 问题一（溢出）—— **整条作废**

**决策：改用「包围盒归一化」（fit-to-view）**，不再用中位边长归一化。

理由（三个参照物全都指向包围盒）：

| 参照物 | 归一化方式 | 出处 |
|---|---|---|
| **GVRRI**（参照的已发表实验） | 包围盒 + 10% 留白 | `resistance.py::plot_network`：`ax.set_xlim(x_min - padding, x_max + padding)` |
| **我们的论文插图** | 包围盒 + 8% 留白 | `paper_figure.py` L139–146 |
| **用户的真实体验** | fit-to-view | — |

**中位边长归一化是这三者中的唯一异类**，而且「溢出 + shrink-to-fit」正是它引入的副作用。

**因此以下全部作废，不需要实现**：

```
✗ shrink-to-fit
✗ k_min 筛图（方案 A / B）
✗ 尺寸下限
✗ 自适应节点半径（方案 D）
✗ 「选图阶段排除会溢出的 ego」这套机制
```

**保留一条**：pilot 时另产一套中位边长版本的刺激做稳健性对比 →
`build_stimuli.py --normalization {bbox, median_edge}`

落实位置：`01 §2.2`（已重写）、`02 §4.4`（已重写）、`02 §7.2 F3`（已标为废弃）。

### 问题二（措辞）—— **已修，且「跨任务错位」已否决**

**修正的措辞矛盾**：

| 位置 | 改动 |
|---|---|
| `01 §8.1` 约束块 | 「① 每张图对被试恰好出现一次」→「① **每个被试对每张图只看到一种布局**」 |

| `01 §8.1` 新增 | 🔴 **trial 数提醒**：T1 与 T4 各跑一次完整 24 张图 ⇒ 共 **48 trial**；误读会得出 24（正好一半，且不报错） |

**关于「跨任务错位」—— 你最初提出的质疑是对的，该优化已否决：**

> 你问：「错位后布局不同是什么意思，布局应该是相同的啊」

**你的直觉与 `02 §6.1` 的原始设计一致**（「每个被试对每张图只看到一种布局」），是我加错位时只改了 `01`、没回头改 `02`，写出了文档矛盾。

**为什么错位其实是更差的选择**：

| | 无错位（**采纳**） | 有错位（**否决**） |
|---|---|---|
| 设计表述 | 「每人每图一种布局」——一句话 | 「每图在两个任务里两种布局」——要解释两层轮转 |
| 污染方向 | **自我**：T1 在 KK 学的 → T4 考 KK | **交叉**：T1 在 KK 学的 → T4 考 FR |
| 偏差可解释性 | ✅「读得懂才记得住」，方向明确 | ❌ 跨布局配对，不可归因 |
| 图片识别 | ⚠️ 可能认出「见过」→ RT 虚高 | ✅ 无 |

**结论**：错位消除了「图片识别」这个小效应，却引入了「交叉污染」这个不可归因的问题——**得不偿失**。

**当前设计**：

```
T1 与 T4 共用同一份「图 → 布局」映射（同一个 offset）
每任务 24 trial，共 48 trial
同一张图在两个任务里是【同一种布局】

残留风险：图结构记忆可能从 T1 迁移到 T4
        方向是【抹平各布局差异】——属保守偏差
缓解：任务分块 + 间隔约 20 分钟；且两任务问的是不同问题
```

## ⚠️ 新增待讨论 · 四：ego 的坐标要不要**重新布局**？

> 由作者 2026-09-28 提出。**这是目前最严重的一条** —— 它可能让 T4 直接测不出东西。

### 现状：直接从全图布局里「截窗口」，没有重新布局

刺激的坐标取自 `bench_pipeline_out_0612_ablation_2/graph_details/<case>_layouts.json`，
那是**整张 case 图（114–1079 节点）**的布局。生成脚本做的事是：

```python
coords = {label: {remap[k]: xy for k, xy in pos.items() if k in remap} ...}
#                                ↑ 整图坐标          ↑ 只筛出 ego 的 60 个节点
```

**即：取整图布局的坐标，只保留 ego 的节点，不做任何重新布局。**

### 文档确实是这么写的

| 出处 | 原文 |
|---|---|
| `docs/01 §9` | 「对每个 ego network，**提取**四种布局的坐标」 |
| `docs/02 §4.4` | 「**取该布局下**、该 ego 所有节点的坐标」 |
| `docs/02 §4.2` | 只强调「诱导子图，**拓扑**不做任何改动」—— 对**坐标**只字未提 |

所以实现是照文档做的。**但文档可能没有意识到「截窗口」与「重新布局」是两回事。**

### 实测：两者差别很大（24 个正式 ego）

对同一批 ego，比较「全图布局截窗口」与「对 ego 子图重新布局」（FR / KK 可重跑；LPFD 见下）：

| 指标 | 窗口（现状） | 重新布局 |
|---|---|---|
| **角均匀度**（FR） | **0.021** | **0.092**（4.4×） |
| **角均匀度**（KK） | 0.077 | 0.124 |
| 结构保持 ρ（FR / KK） | 0.532 / 0.466 | 0.635 / 0.638 |
| 邻域边长 CV（FR / KK） | 0.766 / 0.455 | 0.394 / 0.253 |

> **角均匀度** = `最小相邻边夹角 ÷ (2π/度数)`。1 = 完全均匀，0 = 有两条边重叠。
> 窗口版 FR 是 **0.021**：seed 度数为 32–40，均匀时相邻边应差 ~11°，0.021 意味着
> **最紧的一对边只差 0.2°** —— 视觉上就是两条边**叠在一起**。

**为什么这条最严重**：`docs/03` 明确写着 **T4 是 D2（入射边角度分布）唯一的实验抓手**。
而「截窗口」恰恰把 D2 想优化的东西**提前破坏了**。这正是 `docs/02 §9` 风险表预警的**地板效应**：
「基线都做不好则改进测不出」。

> ⚠️ 但要说公道：窗口**没有抹掉方法差异**（FR 0.021 vs KK 0.077，比值 3.7×，反而更悬殊）。
> 问题是**绝对值全都趋近 0** —— 四种方法**都不可读**，被试只能瞎猜。是**地板**，不是对比度损失。

### 卡在哪：LPFD 的权重不在这个仓库

```
eval/batch_benchmark_pipeline_v2.py:108
    ckpt_path = os.path.join(project_root, "logs", exp_name, "best_model.pth")
eval/batch_benchmark_pipeline_v2.py:313
    OUTPUT_DIRECTORY = "/root/autodl-tmp/bench_pipeline_out_0612_ablation_2"
```

- `logs/` 目录**是空的**，全盘搜不到 `best_model.pth`
- 产出目录写死在 **`/root/autodl-tmp/`** —— 那条管线是在**远程机**上跑的
- 仓库里只有 CoRe-GD 的权重（`eval/gd_models/core_gd/*.pt`），那是**基线**

⇒ **FR / KK / FA2 可以重跑，LPFD 不行** —— 而 LPFD 恰恰是被检验的方法。

### 这其实是两个不同的研究问题

| | **A. 全图布局截窗口**（现状） | **B. 对 ego 子图重新布局** |
|---|---|---|
| 问的是 | 「LPFD 画的**大图**，其局部邻域好不好读？」 | 「LPFD 画**这 60 节点的图**，好不好读？」 |
| 与第 5 章指标一致 | ✅ 第 5 章的 LNP / LAR / LEU 也是在**全图布局**上按节点算的 | ❌ 与第 5 章口径不同 |
| 生态效度 | ✅ 「放大看真实大图的一角」 | ⚠️ 60 节点的小图不是论文的动机场景（动机是「hub 有上百邻居」） |
| 局部质量 | ❌ 实测很差（角均匀 0.021） | ✅ 好得多 |
| 可行性 | ✅ 现在就能做 | ❌ 缺 LPFD 权重 |

**由此引出一个更根本的问题，这才是真正该讨论的：**

> **如果连「把 1000 节点的图放大看一角」时局部角度都糊成一团，
> 那「LPFD 改善 node-centric readability」这个主张，在真实使用场景里还成立吗？**
>
> - **若成立** → A 是对的场景；但 **T4 会地板**，需要换任务或换指标（例如改用逐 trial 易读性评分等主观量）
> - **若不成立** → 论文的主张需要**收窄**为「LPFD 在**中小规模图**上改善局部可读性」

### 需要你决定

| 选项 | 做法 | 代价 |
|---|---|---|
| **A** | 保持现状（截窗口） | 简单；但 T4 很可能地板，且要在论文里解释「为何窗口这么糊」 |
| **B** | 把 24 个 ego 导出成独立图，用**你自己的 pipeline 重跑四种方法**（含 LPFD） | **最干净**；需要你恢复权重或远程跑一次；与第 5 章口径不同，需在论文说明 |
| **C** | 双轨：主实验用 B，另附 A 作「真实场景」对照 | 工作量翻倍，但能同时回答两个问题 |
| **D** | 先不改，**pilot 用 A 跑一次 T4**，看是否真的地板 | 最省事；但 pilot 要招人，且若确认地板就白跑一轮 |

**倾向 B 或 D。** A 的风险是「做完实验才发现测不出东西」；而 D 的 pilot 本来就在计划里，
可以直接用来验证这件事 —— **代价最小、信息量最大**。

> **需要先回答的一个问题：LPFD 的权重能不能恢复？** 能的话 B 才可行。

## 问题一：溢出（中位边长归一化）

### 1.1 规格现状

`02 §4.4` 的归一化流程：

```
1. 算布局中所有边的长度，取中位数 med
2. scale = TARGET_MEDIAN_PX / med          # 建议 TARGET_MEDIAN_PX ≈ 40
3. 所有坐标 × scale
4. 平移到画布中心
5. 若包围盒超出画布，整体再缩小以适配（并记录发生了多少次）
```

**第 5 步只说了「怎么缩」，没有说：**
- 画布留白（margin）取多少
- 缩到多大为止
- **缩了之后的后果是什么**（这一条是本问题要讨论的核心）

### 1.2 实测：中位情形没问题，尾部会坏

全量样本 = **2436** 个（候选 ego × 4 布局），画布 900×620，留白 20px，目标中位边长 40px。

| 布局 | 溢出率 | 最差缩放系数 `k` | 缩放后**实际中位边长** |
|---|---|---|---|
| LPFD | 7.1%（43/609） | 0.606 | 24.2px |
| **KK** | **0.7%（4/609）** | **0.205** | **8.2px** |
| FR | **11.3%（69/609）** | 0.588 | 23.5px |
| FA2 | 10.3%（63/609） | 0.452 | 18.1px |

**总体溢出率 7.3%（179/2436）。**

**中位情形是好的**：四种布局缩放后的「实际中位边长」**中位数都仍然等于 40px**——也就是说在典型情形下，「不同布局边长可比」这个受控性质**保住了**，shrink-to-fit 是温和的。

**尾部才是问题**。

### 1.3 为什么尾部是问题：节点半径是**固定像素**

`01 §2.3` 规定节点是**灰圆、半径 5 像素**（直径 10px），且「节点大小 / 边宽跨图、跨布局完全一致」——这是 GVRRI 的规格，**不随坐标缩放变化**。

所以当某个布局被压到 `k = 0.205`：
- 它的**坐标**被缩到原来的 1/5
- 它的**节点仍然画 5px 半径**
- ⇒ 实际中位边长降到 **40 × 0.205 = 8.2px**，**比节点直径（10px）还小**
- ⇒ **相邻节点直接重叠**

即：shrink-to-fit 对**已经被判定为「摊得太开」的布局**，反而把它们变成了**最挤**的布局。这与归一化想要达到的目的（让各布局的可读性差异只反映布局质量）是相反的。

### 1.4 一个附带发现：`02 §7.2 F3` 引用的数字不属于 case9

`02 §7.2 F3` 写：

> case9 实测：FR **781×909**、FA2 **849×1071**　vs　画布 900×620　→ 确实溢出

**在 case9 上复现不出来。** case9 全部 50 个候选 seed 的包围盒上界是：

| case9 | 最大宽 | 最大高 |
|---|---|---|
| LPFD | 382 | 296 |
| KK | 218 | 187 |
| FR | **316** | **468** |
| FA2 | **386** | **439** |

FR 最大 316×468、FA2 最大 386×439，**都远未到 900**。

真正的极端值全部来自 **case6**：

| ego | k | 包围盒 |
|---|---|---|
| case6-mid deg=13 | 0.205 | **1579 × 2828** |
| case6-high deg=41 | 0.307 | 2012 × 1890 |
| case6-high deg=44 | 0.314 | **2102** × 1850 |

`02 §7.2 F3` 想要论证的方向（「中位边长归一化有利于长边布局、不利于紧凑布局」）**是对的**，但引用的坐标不是 case9 的，写进论文前需要更正。

### 1.5 四个候选做法

**判据必须是 `k_min = min(k_LPFD, k_KK, k_FR, k_FA2)`**——因为 Latin square 会让**每一个入选的 ego 迟早都被分到全部 4 种布局**（见 `01 §8.1`），所以不能只要求「某个布局下能渲染」，必须要求四种**全部**能渲染。因此筛选发生在**选图阶段**，而不是渲染阶段。

候选池 **609** 个 ego，主实验只需要 **24** 个（每度档 8 个）：

| 方案 | 做法 | 通过数 | low | mid | high | high 档**度数中位** | 最差实际中位边长 |
|---|---|---|---|---|---|---|---|
| **A（推荐）** | 选图要求 `k_min ≥ 0.70` | **545** | 471 | 29 | 45 | **40**（与不筛一致） | **28px** |
| B | 选图要求 `k_min ≥ 0.85` | 516 | 453 | 27 | 36 | **36** ⚠️ | 34px |
| C | **不筛**，照 `02 §4.4` 原规格 shrink-to-fit | 609 | 510 | 30 | 69 | 40 | **8.2px**（重叠） |
| D | 筛图 + 节点半径自适应 `r = 5/k` | 545 | 471 | 29 | 45 | 40 | 28px，但**偏离 GVRRI 固定半径规格** |

### 1.6 为什么推荐 A，而不是「完全不缩」（`k_min ≥ 1.0`）

要求**零缩放**当然最干净，但实测显示它有副作用：

| 筛选 | 通过数（需 24） | high 档度数范围 | high 档**度数中位** |
|---|---|---|---|
| 不筛（全体） | 609 | 27–44 | **40** |
| `k_min ≥ 1.0`（零缩放） | 484 | 27–44 | **36** ⚠️ |
| `k_min ≥ 0.85` | 516 | 27–44 | **36** ⚠️ |
| **`k_min ≥ 0.70`** | **545** | **27–44** | **40** ✅ |

注意 `k_min ≥ 1.0`（要求完全不缩放）的通过数有 484，**供给上完全够用**——所以选 0.70 不是「因为 1.0 不够」，而纯粹是为了**保住 high 档的度数分布**。

**`k_min ≥ 1.0` 会把 high 档的度数中位从 40 压到 36——即系统性地剔掉最极端的 hub。** 而 H2 恰恰是「LPFD 的优势**在高 hub 上更大**」，被削掉的正是要测的那一端，会直接削弱核心假设的检验力。

`k_min ≥ 0.70` 时 high 档保持 `deg 27–44、中位 40`，**与不筛完全一致**，同时把最差情形从 8.2px 抬到 28px。

### 1.7 需要讨论的点

1. **这是不是 cherry-picking？** 我的理由是：被排除的是 case6 的病态 ego（KK 把 60 个节点摊成 1579×2828），属**渲染不可用**，不是「挑好看的图」；且判据是**确定性、统一施加**的阈值，与 `02 §7` 要求的「严格遵守确定性算法（§4.2），不人工挑图」不冲突。但这条终究是**选择偏差**，`02 §7` 的「ego 抽取引入的选择偏差」一行需要补上它，并在论文里明确说明。请评估审稿人是否会质疑。
2. **阈值取 0.7 是否合适？** 0.7 对应最差实际中位边长 28px（节点直径的 2.8 倍）。若要更保守可取 0.85（34px），代价是 high 档度数中位降到 36。
3. **方案 D 是否值得考虑？** 半径自适应能同时解决「太挤」和「太小」，但会偏离 GVRRI 的固定半径规格——而「沿用已发表实验的视觉编码」是 `01 §2.3` 的一个卖点。
4. **是否保留第 5 步？** 建议保留作为**断言/兜底**：若启用筛选，构建时第 5 步应当**从不触发**；一旦触发即为 bug。这样「记录发生了多少次」就变成一个可断言的健康指标，而不是一个需要解释的噪声。

## 问题二：措辞（`01 §8.1` 自相矛盾）

### 2.1 原文对照

第二轮修订为 A2 增加了**跨任务错位**（`offset_T4 = offset_T1 + 1`，保证同一张图在 T1 与 T4 里看到的是**不同布局**）。算法改对了，但**同节上方的约束描述没有跟上**：

| 行 | 内容 |
|---|---|
| **L467** | 「① **每张图对被试恰好出现一次**　← 避免记忆污染（见 `02_数据方案.md` §6.1）」 |
| **L497** | 约束表「① 每图一次 \| 每张图 `i` 只出现在一个 `layoutIndex` 上」 |
| **L488** | 「**T1 与 T4 共用同一批 24 张图，每张图必然被看两次。**」 |

**L467 / L497 与 L488 在同一个 §8.1 内直接对立。**

### 2.2 风险

代码块（L477–485 的 `offset_T1` / `offset_T4`）是明确的，照着写没问题。

**但只读约束① 会得出「每个被试总共 24 个 trial」——正好是正确值的一半**（应为 48）。实现者若以约束列表为准，会把流程写短一半，且这个错误**不会报错**，只会静默地少收集一半数据。

### 2.3 建议改法

| 行 | 现在 | 建议 |
|---|---|---|
| L467 | 「① 每张图对被试恰好出现一次」 | 「① **每个任务块内**每张图恰好出现一次」 |
| L497 | 「① 每图一次 \| 每张图 `i` 只出现在一个 `layoutIndex` 上」 | 「① 每块每图一次 \| 每个任务块内，每张图只对应一个 `layoutIndex`」 |
| L499 | 「③ 跨被试均衡 \| …每个 (图, 布局) 组合出现次数相同」 | 补注「**T1 与 T4 分别计**」 |

### 2.4 需要讨论的点

跨任务错位把「同图**同**布局重测」（最坏）降级为「同图**不同**布局重测」，**但重复本身仍在**——每张图仍被每个被试看两次。

- **接受**（当前状态）：两任务各 24 trial，共 48，约 45–50 分钟。风险是记忆污染方向**抹平各布局差异**，会让实验「失败但你不知道」。
- **替代方案：拆分图池** —— T1 用 12 张、T4 用另外 12 张，每张图全程只出现一次。总 trial 降到 32（约 30 分钟），代价是每个 (布局 × 度数档) 单元**只剩 1 张图**（现在 2 张），统计功效下降。

请评估：以现在的设计（接受重复 + 错位）投出去，审稿人对「同图重复呈现」的容忍度如何。这决定了是维持 48 trial 还是改为 32。

```python
G = nx.Graph()
for n in d['nodes']: G.add_node(n.get('name') or n.get('id'))
for e in d['links']:
    s, t = e.get('source'), e.get('target')
    if s is not None and t is not None and s != t: G.add_edge(s, t)
```

**ego 抽取**（`02 §4.2`，已逐行复现 `02 §3.1` 的实测表 8/8）：

```python
def build_ego(G, seed, n=60, hops=3):
    seen = {seed}; q = deque([(seed, 0)])
    while q and len(seen) < n:
        u, h = q.popleft()
        if h >= hops: continue
        for v in sorted(G.neighbors(u), key=lambda x: -G.degree(x)):
            if v not in seen:
                seen.add(v); q.append((v, h + 1))
                if len(seen) >= n: break
    return G.subgraph(seen).copy()
```

**缩放系数**（画布 900×620，margin 20，`TGT = 40`）：

```python
med = statistics.median(edge_lengths)          # 该布局下所有边的长度中位数
sc  = TGT / med
w, h = bbox(所有坐标 * sc)
k = min(1.0, (900 - 2*20)/w, (620 - 2*20)/h)    # k < 1.0 即溢出，需 shrink-to-fit
# 缩放后实际中位边长 = TGT * k
```

**候选池过滤**（得到 609）：度数档 5–12 / 13–26 / ≥27；`ego N ≥ 40`；星型排除判 **seed 自身**在 ego 内的度数 `deg_in_ego(seed) ≥ 0.8×(N−1)`（注意：**不是** ego 的最大度——ego 内含高度数 hub 是期望的，正是 T4 的配对来源）。

## 附录 B：确定性要求（构建时必须遵守）

`nx.betweenness_centrality` 的浮点累加顺序**依赖节点迭代顺序**，而 ego 节点集来自一个 `set`，Python 字符串 `set` 的迭代顺序**跨进程可变**（hash randomization）⇒ 数学上完全相等的介数值会出现最后一位浮点的差异。

后果：用 `bc[v] >= sorted(bc.values())[int(0.8*len(bc))]` 判定 bridge 时，在大量并列的情形下（low 档 510 个候选里 **75 个恰好落在阈值上**），比较结果随 ULP 噪声翻转 ⇒ **同一份数据跑出 461 / 462 / 464 / 465 四个不同的 bridge 数**。

正确做法：**先量化再定序**

```python
ranked = sorted(E.nodes(), key=lambda x: (-round(bc[x], 9), str(x)))
k = max(1, int(round(0.2 * len(ranked))))
is_bridge = v in set(ranked[:k])
```

修好后本机在 `PYTHONHASHSEED ∈ {1, 7, 99999, 31337}` 下证据文件 md5 完全一致。

> **这条对 `build_stimuli.py` 是硬要求**：刺激选取必须逐位可复现，否则换一台机器会选出**不同的 24 张图**，实验无法复现。
