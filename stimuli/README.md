# 刺激数据说明

> 由 `tools/build_stimuli.py --normalization bbox` 生成，请勿手改。

## 数据源

`data/dataset/benchmark_test_0312/` 里 **≤110 节点的原生图**（26 张）。

**不裁剪、不重新布局** —— 图本身就是刺激，坐标直接取自 `<graph>_layouts.json`。
这是 2026-09-28 的设计改版：原方案从 case 大图里截 60 节点 ego 窗口，
实测那个窗口的局部几何被破坏（seed 处角均匀度只有 0.02–0.09），
而 T4 恰恰测的就是角度分布 —— 等于把要测的信号提前毁掉。

## 选图规则（docs/02 §4.2）

1. 读 `*.json` + `*.graphml`，筛出 **n ≤ 110** 的 → 26 张
2. 两档：**低 = 度 2–8** ／ **高 = 度 ≥16（无上限）**
3. 按**图名升序**，每档取前 8 张
4. 每图挑 1 个目标节点（档内规则见下）
5. 坐标**原样使用**，只做包围盒归一化（留白 = 画布每边 8%）

> ⚠️ **确定性**：排序全用字符串键，无浮点比较。
> 已实测 `PYTHONHASHSEED ∈ {1,7,99999,31337}` 下产物 md5 完全一致。

### 档内怎么挑目标节点 —— `--target-rule top`

⚠️ **文档没有规定档内怎么挑**（docs/02 §4 步骤 3 只说「每图挑 1 个该档的目标节点」）。
这是实现方补的规则，三种取法：

| rule | 低档取到 | 高档取到 | 跨档对比度 | 风险 |
|---|---|---|---|---|
| **`top`（当前）** | ≈8 | 图的最大度 | 2×–4× | 无 |
| `bottom` | ≈2 | 图的最大度 | 8×–16× | 低档只有 2 个邻居 → T1 可能天花板 |
| `mid` | ≈5 | 图的最大度 | 3×–6× | 折中 |

默认 `top`（档内最像 hub 的那个）：在低档也给出有实质邻域的节点，
避开 docs/02 §3.2 自己点名的低度天花板风险。追求最大对比度用 `--target-rule bottom`。

## ⚠️ 与文档的三处不一致（已按最佳判断处理，**需作者确认**）

### 1. `docs/03 §3.5` 的档位是旧版，且低档**数学上无解**

它写「高试次 `deg_max ∈ [16,25]`；**低试次两个节点都在 [5,8]**」+「比值 ≥2」。
但 [5,8] 内最大比值是 **8/5 = 1.6 < 2** —— **无解**。
本实现按 `docs/02 §3.2`（更新且自洽）：低 2–8 ／ 高 ≥16 无上限。
按 2–8，低档合法配对为 (4,2)(5,2)(6,2)(6,3)(7,2)(7,3)(8,2)(8,3)(8,4)。

### 2. 高档上限冲突

`docs/02 §3.2` 说「≥16 **无上限**」，但 `docs/03 §3.5` 说 `[16,25]`、
`docs/02 §7.2 F2` 说「上限是 **25**」。实际选出的图最大度是 **33** —— 超过 25。
本实现按 §3.2 的「无上限」。

### 3. 两档重合（本实现**默认不重合**）

`docs/02 §4.2` 写「若某张图在两档都被选中 → 允许」，但实测有 **5 张重叠**
（GD2 / GD5 / GD6 / Babel / aves），这样只有 11 张不同的图，
且这 5 张会被同一被试看 **4 次**（T1低 + T1高 + T4低 + T4高）—— 
与 `docs/02 §7.2 F1` 的「每张图见 2 次」自相矛盾。
本实现默认**不重合**（当前 `--allow-overlap` = False），先满足候选更少的高档，再从剩下的取低档。

## ⚠️ 必须在论文 Limitations 里报告的取舍（docs/02 §7.2）

### F1 — 跨任务图重复

T1 与 T4 **共用同一批 16 张图、同一份「图 → 布局」映射**。
每被试 32 trial ⇒ 每张图见 **2 次，两次是同一种布局**。
残留风险：T1 学到的结构可能迁移到 T4，方向是**抹平各布局差异**（保守偏差）。
缓解：任务分块；两个任务问的是不同问题。

> 「跨任务错位」曾被考虑并**否决** —— 它把「自我污染」换成「交叉污染」，不可归因。

### F2 — 没有真正的 hub

刺激图的节点度数上限是 **33**
（自选小图的限制）。论文第 1 章的动机是「hub 有上百个邻居」——本实验**测不到那个尺度**。
缓解：把「hub」口径明确为**相对定义**（度数 > 全图均值 + 一个标准差），并收窄动机句。

### F3 — 未做用户实验的案例研究

本轮只做到**编码层**（「布局更好读」），不主张**领域层**（「对黑灰产分析有用」）。

## 归一化

**包围盒（fit-to-view）**，留白 = 画布每边 8%（可用区 84%）：

```
scale = min( (W × 0.84) / w, (H × 0.84) / h )
```

⚠️ 留白必须从**画布像素**里扣。早期版本写作 `pad = 0.08 × max(w,h)` 再
`(W − 2·pad)/w`，把原坐标单位当像素减了 —— 实测约 **75% 的图会裁掉边界节点**，
且 LPFD/KK/FR 全裁、FA2 不裁（各方法原坐标量级差 160 倍以上）。

> pilot 要求：另跑一套 `--normalization` 的刺激，对比结论方向是否稳定（docs/02 §7.3）。

## 图素养前测

**已取消**（`CONFIG.survey.literacy = false`）。理由见 `docs/03 §6.3`：
Zoss NVL 量表本体拿不到（仓库只提供分析脚本）；GGR 测的是统计图表不是网络图（构念不对）；
自编则违背「不适用就找权威替代，不要自己构建」的原则；且**信度不够的协变量会降低功效**。
替代：人口学里的「图论熟悉度自评」作协变量 + 分析里报告参与者方差成分。
